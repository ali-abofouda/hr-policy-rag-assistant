# موديول 11: بناء حاوية Docker وتنسيق الخدمات والتحكم في الوصول (Containerization, Compose & Access Control)

## 1. مواصفات الحاوية الإنتاجية (Production Container Specifications)

لضمان عمل مساعد سياسات الموارد البشرية بكفاءة عالية على السحابة، تم تجهيز صورة Docker وفق المعايير التالية:
* **الصورة الأساسية (Base Image):** `python:3.11-slim` لتوفير بيئة تنفيذ مستقرة وخفيفة الحجم (أقل من 350 ميجابايت).
* **مدير الحزم (Package Manager):** `uv` لتحقيق تثبيت سريع للاعتماديات دون استهلاك ذاكرة غير ضروري.
* **تقنية التخزين المؤقت المسبق (Build-time Model Caching):** يتم استدعاء نموذج `fastembed` الخاص بـ `Qdrant/bm25` أثناء مرحلة بناء الصورة وحفظه في `/root/.cache`. هذا يمنع الحاوية من تنزيل النموذج عند كل بداية تشغيل (Cold Start) على Google Cloud Run، ويخفض زمن الإقلاع إلى أقل من ثانيتين.
* **منفذ الاستماع (Port):** المنفذ القياسي `8080`.
* **فحص الجاهزية (Health Check):** مسبار دوري يستهدف المسار `/_stcore/health` الخاص بخادم Streamlit للتأكد من قدرة الحاوية على استقبال الطلبات.

## 2. هيكل الخدمات المصغرة (Docker Compose Microservices)

يحتوي ملف `docker-compose.yml` على ثلاثة خدمات معزولة:

1. **خدمة `app`:** الخدمة الأساسية التي تشغل واجهة المستخدم التفاعلية لـ Streamlit على المنفذ `8501:8080`.
2. **خدمة `ingest`:** خط أنابيب استيعاب وفهرسة المستندات المتجهية في Qdrant. تتبع بروفايل `tools` وتعمل عند الطلب فقط:
   ```bash
   docker compose --profile tools run --rm ingest
   ```
3. **خدمة `eval`:** خط أنابيب التقييم المؤتمت عبر LangSmith و OpenEvals. تتبع بروفايل `tools`:
   ```bash
   docker compose --profile tools run --rm eval
   ```

## 3. طبقة التحكم في الوصول والمصادقة (Google OAuth Access Control)

تطبق دالة `verify_access_control()` في `app.py` سياسة أمان صارمة ومزدوجة:

1. **فحص وجود أسرار التوثيق (`is_auth_configured`):**
   * إذا لم تكن كتلة `[auth]` موجودة في `st.secrets` (كما في بيئة التطوير المحلية)، يعمل التطبيق في النمط المفتوح دون توقف أو انهيار.
2. **التحقق من هوية الموظف (`st.user`):**
   * عند النشر السحابي، تُلزم البوابة المستخدم بتسجيل الدخول عبر حسابه المؤسسي في Google.
   * يتم استخراج البريد الإلكتروني للمستخدم ومطابقته مع القائمة المعتمدة في متغير البيئة `ALLOWED_EMPLOYEE_EMAILS`.
   * إذا كان البريد غير مصرح له، يتم حجب التطبيق فوراً وعرض شاشة `Access Denied` ومنع تنفيذ أي استعلامات RAG.
